1. プロジェクト概要・目的

1.1 背景

プログラミング初学者（小学生高学年〜大人の未経験者）は、コード記述時の構文エラーや、期待した結果と異なる論理エラーに直面した際、難解なエラーメッセージや解決の糸口が掴めず、挫折しやすい課題を抱えている。

1.2 目的

白紙からコードを一から書き上げる実践的な学習習慣を定着させ、自律的にエラーを解決できる力を養う。 ローカルAIによる初学者向けの段階的ヒント提示、実行結果の差分解説、組み込み関数辞書、成長記録の蓄積により、挫折せず楽しく継続できるプログラミング学習環境を提供する。

1.3 想定利用者（ターゲット層）

  • 主要ターゲット: 小学校高学年〜中高生、大学・専門学校の未経験生、社会人初学者
  • 利用シーン: 教育機関・学校のPC教室（ローカル環境）、自宅PCでの自習

2. システム化方針・スコープ

2.1 言語スコープ

  • 実行・採点対象言語: Python（Windows用 Embeddable Package をアプリに同梱し、利用者の環境構築を不要とする）
  • 比較表示対象言語: Java、JavaScript（構文や書き方の対比・辞書参照のみ提供し、初期版では実行環境は提供しない）

2.2 AI・データ処理方針

  • ローカル推論完結: AI分析・ヒント生成はユーザー端末内（ローカル）で処理し、通信費の抑制およびオフライン学習を可能とする。
  • データ保存のハイブリッド分離:
    • 端末内保存: ユーザーが入力したコード全文、一時編集内容、個人設定（プライバシー保護と即時オートセーブ）
    • クラウド同期: ログイン時の学習履歴（合否、得点、エラー種別、達成日時、バッジ獲得状況）※コード本文は原則クラウドに送信しない

3. 業務・利用フロー要件

  1. 学習開始・モード選択: 利用者は「自由創作モード」または「課題演習モード」を選択して開始する。
  2. コード記述と自動保存: 白紙エディタにコードを記述する。編集中の内容はバックグラウンドで端末内に定期自動保存（オートセーブ）される。
  3. 実行・自動検証:
    • 自由創作時: 同梱Pythonで実行し、標準出力または標準エラーを表示する。
    • 課題演習時: 自動テストケースを実行し、要件達成度と実行結果を機械的に検証・部分点付与する。
  4. エラー解説・段階的AI支援:
    • 構文エラー時は平易な日本語で原因を解説する。
    • 論理エラー時は「期待する結果」と「実際の出力」の差分を明示する。
    • AIヒントは答えを即答せず、「着眼点」→「考え方」→「修正方針（希望時のみ修正例）」の段階式で提示する。
  5. 記録蓄積とクラウド同期: 採点結果や克服したエラーは端末内に記録され、ログイン時はBaaS（NoSQL）へ非同期で同期送信される。

4. 機能要件（Functional Requirements）

要件ID 要件名 要件仕様・詳細 優先度
FR-01 自由創作モード 白紙エディタでPythonコードを自由に記述・実行し、標準出力および標準エラーをコンソールに表示できること。ファイル保存にも対応すること。 必須
FR-02 課題演習モード 課題文、制約条件、期待出力を表示し、白紙からコードを作成してテスト実行・自動採点できること。 必須
FR-03 自動採点・部分点機能 100点満点（要件達成度50点 / 実行結果30点 / コード妥当性20点）で採点し、80点以上かつ無エラーで合格判定を行うこと。テスト失敗時でも部分点を付与すること。 必須
FR-04 段階的AIヒント 答えを即座に教えず、「着眼点」「考え方」「修正例（希望時）」のステップ式でヒントを提供すること。 必須
FR-05 ローカルAI推論基盤 端末内の軽量LLMを用いて推論を行い、外部APIなしで動作すること。モデル未導入時でもPython実行や通常エラー表示を妨げないこと。 必須
FR-06 コード自動保存 入力中のコードを定期的に端末内へ自動保存し、予期せぬアプリ終了時も再起動時に直前の状態を復元できること。 必須
FR-07 学習履歴クラウド同期 課題結果、得点、エラー種別、解決状況、獲得実績をクラウドDBと同期できること。コード本文は送信しないこと。 必須
FR-08 ゲスト・ログイン切替 ゲスト状態（端末内保存のみ）とログイン状態（クラウド同期）の双方に対応し、ログイン時に端末内ログをマージできること。 必須
FR-09 関数・構文辞書 基本構文や組み込み関数（print, len, if, for等）の使い方を検索・閲覧でき、AIヒントからの逆引きリンクに対応すること。 必須
FR-10 既習言語構文比較 Pythonの構文とJava/JavaScriptの書き方を左右に対比表示できること（静的データ表示）。 必須
FR-11 コーディング補助 ワンクリックでのコード自動整形（インデント等）および基本構文スニペットの挿入ができること。 必須
FR-12 やさしさ表示切替 UI表記を「こどもモード（ふりがな・やさしい言葉）」と「大人モード（標準表記）」で切り替えられること。 必須
FR-13 アチーブメント機能 課題達成や学習継続、エラー解決に応じてバッジ（実績）を付与し、一覧表示できること。 必須

5. 非機能要件（Non-Functional Requirements）

5.1 性能・パフォーマンス要件

項目 仕様基準値 設計方針・備考
コード実行応答時間 実行指示から1.0秒以内に出力描画 通常の短文・入門コードの場合。ローカル同梱Pythonの即時起動により実現。
AI推論応答時間 CPU推論時で5〜10秒以内を目標 推論中はUIに「分析中...」のスピナーを表示し、非同期で描画する。
アプリ起動時間 初回起動後、3.0秒以内にメイン画面表示 Tauri v2 による軽量バイナリ構成により、Chromium起動待機を排除。

5.2 安全性・セキュリティ要件

項目 仕様基準値 設計方針・備考
プロセス実行時間制限 最大5.0秒でタイムアウト強制停止 無限ループ等の暴走コードに対し、Rust側から子プロセスツリーごと強制終了する。
コンソール出力バッファ制限 最大1.0 MiBで出力を打ち切り 無限print等によるメモリ枯渇（OOM）を防止し、上限到達時は警告メッセージを付与して終了。
コード全文のプライバシー保護 クラウドへコード本文は送信しない 学習者の著作権とプライバシーを守るため、送信対象は得点・エラー種別・ハッシュ値等に限定する。

5.3 信頼性・可用性要件（フォールバック）

項目 仕様基準値 設計方針・備考
オフライン自立動作 ネットワーク切断時でも主要学習を100%継続可能 Python実行、機械的テスト、ローカル保存、辞書閲覧はオフラインで完全動作させる。
AI障害時の縮退運転 モデル破損・未導入時もアプリを落とさない AIが動作しない環境でも、エディタ編集・Python実行・機械採点・辞書参照は継続動作させる。
データ整合性・再送制御 オフラインキューによる未同期データの保護 オフライン時の学習履歴は端末内に一時保持し、ネットワーク復帰時に安全に再送同期する。

5.4 ユーザビリティ・アクセシビリティ要件

項目 仕様基準値 設計方針・備考
画面リサイズ・可変分割 最低解像度 1366×768 に対応 エディタ、コンソール、AIヒント、辞書のパネル境界をマウスドラッグで伸縮可能とする。
漢字・難解用語への配慮 ルビ（ふりがな）表示対応 小学生高学年でも一人で読み進められるよう、専門用語を平易にし、ふりがな切り替えを設ける。
