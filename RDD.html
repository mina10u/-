システム要件定義書 (RDD)

プログラミング学習 AI誤り分析アシスタント（CodeLab）[cite: 1]

システム種別: Windows デスクトップアプリ[cite: 1]
開発フレームワーク: Tauri v2 (Rust + React)[cite: 1]
改訂日時: 2026年10月23日 11:35
開発体制: チーム（6名）[cite: 1]

1. プロジェクト概要・背景・目的

1.1 背景

プログラミング初学者（特に小中学生〜大人の未経験者）は、コード記述時の構文エラーや、期待通りに動かない論理エラー（期待値との相違）に直面した際、エラーメッセージの難解さや解決の糸口が掴めないことで挫折しやすい[cite: 1]。

1.2 目的

初学者が白紙からコードを書く習慣を身につけ、自律的にエラーを解決できるよう支援する[cite: 1]。ローカルAIによる初学者向けの段階的ヒント、差分解説、組み込み辞書、マルチファイル管理、成長記録の蓄積により、「挫折せずに楽しく継続できる学習体験」を提供する[cite: 1]。

1.3 対象ユーザー

  • 主要ターゲット： 小学校高学年〜中高生、およびプログラミングを初めて学ぶ大学生・専門学校生・社会人[cite: 1]
  • 利用環境： 学校・教育機関のPC教室、自宅の個人用Windows PC[cite: 1]

2. システム化方針・スコープ

2.1 対象言語

  • 実行・採点対象： Python（Windows用Embeddableランタイムを同梱配布し、ユーザー環境構築不要）[cite: 1]
  • 比較表示対象： Java、JavaScript（初期版では実行せず、構文対比・学習辞書表示のみ）[cite: 1]

2.2 AI・データ管理方針

  • ローカルAI： 推論は端末内（ローカルPC）で完結。外部通信料なし、オフラインでも学習継続可能[cite: 1]。
  • データ管理：
    • 端末内保存： ユーザーが編集中のコード本文、自由創作プロジェクトの全ファイル群、一時設定（プライバシー保護と即時オートセーブ）[cite: 1]。
    • クラウド同期： ログインユーザーの学習履歴（合否、スコア、エラー種別、日時）、バッジ獲得実績（コード本文は原則送信しない）[cite: 1]。

3. 業務・利用フロー要件

  1. 学習モード選択： 「自由創作モード」または「課題演習モード」を選択して開始[cite: 1]。
  2. コード記述・プロジェクト管理：
    • エディタへのコード入力時、作業内容はローカルへ自動一時保存（オートセーブ）[cite: 1]。
    • 自由創作時、同一プロジェクトフォルダ内の複数ファイル（新規作成・削除・リネーム・タブ切替）を管理し、別ファイルを参照しながら実装を進めることが可能。
  3. 実行と自動検証：
    • 同梱Pythonが安全な制限下でコードを実行（プロジェクトフォルダを作業ディレクトリとして実行）[cite: 1]。
    • 課題演習時はテストケースに基づき自動採点[cite: 1]。自由創作時は同一フォルダ内の import を含む複数ファイル間プログラムを実行。
  4. フィードバック・AI支援・エラージャンプ：
    • エラー発生時は初学者向けの噛み砕いた日本語解説を表示[cite: 1]。
    • 呼び出し先ファイルでエラーが発生した際、呼び出し元と呼び出し先の両方のコードを参照した上で「双方の視点からの具体的な修正提案」を提示し、ワンクリックで該当コードへ遷移・修正可能。
    • 論理エラー時は期待出力と実際出力の差分を明示[cite: 1]。
    • AIヒントは「着眼点 → 考え方 → 修正例（希望時）」の3段階で提供[cite: 1]。
  5. 記録と同期：
    • 採点結果はローカルに蓄積され、ログイン状態であればクラウドサーバーへ非同期送信[cite: 1]。

4. 機能要件一覧 (FR: Functional Requirements)

要件ID 要件名 概要・詳細要件 優先度
FR-01 自由創作モード 白紙のエディタでPythonコードを自由に記述・実行し、標準出力・標準エラーを表示できること[cite: 1]。 必須
FR-02 課題演習モード 課題文、目標、期待出力を表示し、白紙からコードを作成してテストできること[cite: 1]。 必須
FR-03 自動採点機能 100点満点（要件達成度50点 / 実行結果30点 / コード妥当性20点）で採点し、80点以上かつ無エラーで合格判定。テスト失敗時は部分点を付与すること[cite: 1]。 必須
FR-04 段階的AIヒント エラーに対し、答えを直接出さず「着眼点」「考え方」「修正コード例（希望時）」の3段階で支援を提供すること[cite: 1]。 必須
FR-05 ローカルAI推論基盤 端末内の軽量LLMで推論を行い、外部APIなしで動作すること。モデル未導入時でもPython実行を停止しないこと[cite: 1]。 必須
FR-06 コード自動保存 入力中のコードを数秒間隔で端末内に自動一時保存し、再起動時に直前の状態を復元できること[cite: 1]。 必須
FR-07 学習履歴クラウド同期 課題結果、得点、エラー種別、解決状況、実績をクラウドDBと同期できること（コード本文は非送信）[cite: 1]。 必須
FR-08 ゲスト・ログイン切り替え ゲスト状態（ローカル保存のみ）とログイン状態（クラウド同期）に対応し、ログイン時に端末内ログをマージできること[cite: 1]。 必須
FR-09 初学者向け構文辞書 基本構文や関数（print, len, if, for等）の使い方を検索・閲覧できること[cite: 1]。 必須
FR-10 既習言語構文比較 Pythonの構文とJava/JavaScriptの書き方を左右に対比表示できること（静的データ）[cite: 1]。 必須
FR-11 コーディング補助 ワンクリックでのコード自動整形および基本構文スニペットの挿入ができること[cite: 1]。 必須
FR-12 やさしさ表示切替 UI表記を「こどもモード（ふりがなあり）」と「大人モード（標準表記）」で切り替えられること[cite: 1]。 必須
FR-13 アチーブメント機能 課題達成や学習継続、エラー解決に応じてバッジを付与し、一覧表示できること[cite: 1]。 必須
FR-14 ワークスペース・複数ファイル管理 自由創作モードにおいて、ローカルのプロジェクトフォルダ内の複数ファイル（新規作成・削除・リネーム・ファイルツリー表示・タブ切り替え）を管理でき、作成したプログラム間を自由に行き来して閲覧・編集できること。 必須（新規）
FR-15 ファイル間実行 ＆ 両コード参照エラー解析・修正提案 同一プロジェクトフォルダ内の別ファイルを import 実行できること。別ファイル起因のエラー発生時はTracebackを解析し、呼び出し元と呼び出し先の両コードを参照した上でエラー原因と双方の視点からの具体的な修正提案（どちらをどう直すべきか）をAIが提示し、該当行へワンクリック遷移できること。 必須（新規）

5. 非機能要件 (NFR: Non-Functional Requirements)

5.1 性能・パフォーマンス

  • コード実行応答： 通常のコード実行は、ボタン押下から1秒以内に標準出力・エラーを表示すること[cite: 1]。
  • AI応答速度： CPU推論環境において5〜10秒以内を目標とし、推論中は「分析中」UIを表示すること[cite: 1]。
  • 起動時間： アプリ起動操作から3秒以内にメイン画面を表示すること[cite: 1]。

5.2 安全性・セキュリティ

  • プロセス隔離・リソース制限：
    • コード実行時間は最大5秒とし、超過時はプロセスツリーを強制終了（タイムアウト）すること[cite: 1]。
    • 出力バッファの上限は合計1MiBとし、無限出力によるクラッシュを防止すること[cite: 1]。
    • ファイルアクセスのスコープ制限： プログラム実行時、import やファイル参照を許可する範囲は「該当プロジェクトフォルダ（作業ディレクトリ）の配下」に限定し、システム重要ディレクトリやユーザーの他領域への不正アクセスを防止すること。
  • プライバシー保護： ユーザーのコード本文全文はクラウドDBへ送信せず、メタデータやハッシュ値のみを送信すること[cite: 1]。

5.3 信頼性・可用性（フォールバック）

  • オフライン動作保証： インターネット未接続時でも、コード編集・実行・辞書参照・端末内保存を継続できること[cite: 1]。
  • AI障害時の縮退運転： AIモデルのダウンロード中や推論失敗時でも、Python実行や機械的テストを落とさず学習を継続できること[cite: 1]。

5.4 ユーザビリティ

  • 初学者・小中学生が直感的に操作できるよう、専門用語を避けた親しみやすい日本語を採用すること[cite: 1]。
  • 1366×768以上の解像度で快適に操作可能なリサイズレイアウト（ファイルツリー、マルチタブ、エディタ、コンソール、AIパネル）とすること[cite: 1]。
