1. アプリ概要・目的

小学生高学年から大人までのプログラミング初心者が、自分で一からコードを書きながらエラーや疑問を直感的に解消できるデスクトップアプリケーション。「自由創作」と「一から書く課題演習」の2モードを用意し、ローカルAIによるエラー・論理分析、クラウドによる学習履歴同期で楽しく学習をサポートします[cite: 3]。初期リリースではPythonに特化して完成度を高め、将来的な複数言語展開に備えます[cite: 2]。

  • ターゲット層: 小学生高学年、中高生、大学・専門学校生、社会人のプログラミング初学者[cite: 3]
  • コア体験: Python特化の堅実なエディタ・実行環境、ローカルAIによるやさしいエラー・差分解説、クラウド同期型の成長カルテ、AIによる課題採点（80点以上合格）、アチーブメント獲得の統合学習体験[cite: 2, 3]

4. 追加詳細仕様（AI・クラウド・採点・オフライン）

① 初期リリースにおける言語方針

  • Python特化: 初期リリース（v1.0）ではPythonのみに絞り、エディタ・実行・採点・AI分析の完成度を最優先で高める。将来的な複数言語（JavaScript等）追加に備えて実行処理層は分離設計とする[cite: 2]。

② ローカルAI仕様

  • 実行場所: ユーザーのPC内（外部APIに依存しないため、オフラインでもエラー解説やチャットが利用可能）[cite: 2, 3]。
  • 入力・出力: コード、実行結果、エラー情報、課題文を入力し、初心者向け解説・問題箇所・改善ヒントを出力[cite: 2, 3]。

③ クラウド保存・学習履歴の同期ルール

  • 保存データ: ユーザーID、エラー履歴（発生日時、種類、解決状態）、修正ログ（コード変遷）、学習進捗（課題達成状況）、アチーブメント、辞書お気に入り[cite: 2, 3]。
  • 同期フロー: ログイン後にサーバーから最新データを取得 ➔ 記録作成時に自動送信 ➔ 失敗時は未同期として保持しオフライン再送[cite: 2]。

④ AIによる課題採点の仕様と例外ルール

  • 採点配点（合計100点満点・80点以上合格）[cite: 2]:
    • 要件達成度: 50点（指定された処理を満たしているか）[cite: 2]
    • 実行結果: 30点（テスト入力に対する出力が期待値と合うか）[cite: 2]
    • コードの妥当性: 20点（ローカルAIによるコードの適切さ評価。模範解答と異なっていても正しく動作すれば合格とする）[cite: 2]
  • 例外ルール:
    • 構文エラーや実行時エラーがある場合は合格判定としない[cite: 2]。
    • 必須テスト失敗時は点数・フィードバックに反映[cite: 2]。
    • AI応答失敗時は採点不能として再試行（仮の合格点としない）[cite: 2]。
    • アプリ側の実行障害と学習者のコードエラーを明確に区別する[cite: 2]。

⑤ オフライン・ログイン仕様

認証状態 ネットワーク 利用できる機能・動作[cite: 2]
ゲスト オンライン ローカル機能を利用。クラウド同期はログイン後に実施[cite: 2]。
ログイン済み オンライン ローカル機能、クラウド履歴の取得・同期[cite: 2]。
ゲスト / ログイン オフライン Python実行、ローカルAI、端末内の保存データを利用（未同期データは保留）[cite: 2]。

5. 開発の順番と6名チーム分担案

段階的実装のステップ

  1. 土台を作る (最優先): Tauri v2の起動、React画面、Rustとの連携[cite: 2]。
  2. Pythonエディタと実行: コード入力、実行ボタン、標準出力、エラー表示、タイムアウト制御[cite: 2]。
  3. 課題演習と自動採点: テストケース、期待値比較、機械的採点からAI評価への拡張[cite: 2]。
  4. ローカルAI接続: エラー解説、論理エラーヒント、チャット、課題評価の統合[cite: 2]。
  5. 保存・学習履歴・ゲスト機能: 端末内保存、成長カルテ、アチーブメント、クラウド同期[cite: 2]。
  6. 学習支援と配布準備: 辞書、ふりがな、コード整形、インストーラー仕上げ[cite: 2]。

6名チームの担当分け

担当ロール 主な作業内容[cite: 2]
1. 画面担当 エディタ、コンソール、画面遷移・UI実装[cite: 2]。
2. 実行担当 Rust連携、Pythonプロセス実行、停止処理・安全性管理[cite: 2]。
3. AI担当 ローカルモデル選定、推論処理、エラー解説プロンプト設計[cite: 2]。
4. 課題担当 課題データ、テストケース、採点ロジックの構築[cite: 2]。
5. サーバー担当 ユーザー認証、Web API、データベース、履歴同期[cite: 2]。
6. 統合・テスト担当 保存処理、共通データ形式定義、結合試験、配布確認[cite: 2]。
