本書は、既存仕様書と今回の修正案を統合した改訂版。実装方針として決定した事項と、実装着手前に選定が必要な事項を区別する。

1. アプリ概要・目的

小学生高学年から大人までのプログラミング初学者が、コードを自分で書き、実行結果やエラーを確認しながら学習できるデスクトップアプリケーションを提供する。学習モードは「自由創作」と「課題演習」の2種類とし、ローカルAIによるエラー分析・段階的ヒント、課題テストによる採点、辞書・他言語構文比較、学習記録の同期を備える。

  • 初期対応言語：Python（実行対象）。Java / JavaScript は構文比較・説明の対象とし、初期版では実行環境を提供しない[cite: 3]。
  • 保存方針：編集コードは端末内、学習記録はログイン時にクラウドへ保存・同期する[cite: 3]。
  • AI方針：原則ローカルAIを利用する。AIが利用できなくても、編集・実行・テスト・保存を継続できる[cite: 3]。
  • 合格基準：採点が完了し、合計80点以上、かつ構文エラー・実行時エラー・タイムアウトがないこと[cite: 3]。

4. 課題採点仕様

4.1 配点

評価項目 配点 評価方法
要件達成度[cite: 3]50点[cite: 3]課題の要求事項を満たしているかを評価する。チェック項目ごとの配点は課題定義に保持する[cite: 3]。
実行結果[cite: 3]30点[cite: 3]自動テストケースの成功数・重要度に応じて算出する[cite: 3]。
コード妥当性[cite: 2]20点[cite: 3]読みやすさ、適切な構造、課題に対する妥当性を評価する。AI評価を使う場合は理由を記録する[cite: 3]。
合計[cite: 3]100点[cite: 3]各項目の点数を合算する[cite: 3]。

テストケースの個別配点は課題データに明示し、実行結果30点の合計が必ず30点になるよう検証する。テストケースの配点が未設定の課題は採点を開始できない[cite: 3]。

4.2 合否・部分点

  • 合計点は0～100の整数とする。各評価項目の点数はそれぞれの配点を超えない[cite: 3]。
  • 採点完了かつ80点以上で、構文エラー・実行時エラー・タイムアウトがない場合のみ合格とする[cite: 3]。
  • テストが一部失敗した場合は成功テスト分の点数を付与し、失敗したケースと期待値・実際値（機密情報を含まない範囲）を表示する[cite: 3]。
  • 構文エラー・実行時エラー・タイムアウト時は合格不可。採点できる項目のみ部分点を表示し、評価できない項目は0点と断定せず「未評価」として区別する[cite: 3]。
  • AI評価に失敗した場合、AI評価を必要とする採点は「採点未完了」とする。暫定点を合格点として扱わず、再試行またはAIなしで利用可能なテスト結果のみ確認できるようにする[cite: 3]。
  • 合否は保存された点数だけでなく、採点状態と実行状態から決定する。UI側の表示値のみで合否を判定しない[cite: 3]。

4.3 ヒント

  1. 第1段階：どの条件・処理を見直すべきかを示す[cite: 3]。
  2. 第2段階：関連する構文や考え方を説明する[cite: 3]。
  3. 第3段階：必要な場合に限り、短いコード例や修正例を示す[cite: 3]。

5. Python実行の安全性・制限

以下は初期実装の基準値案であり、対象PCでの負荷試験とセキュリティ検証後に確定する[cite: 3]。

項目 初期基準案 動作
実行時間[cite: 3]通常実行・各テスト：最大5秒[cite: 3]超過したら実行プロセスとその子プロセスを停止し、タイムアウトとして記録する[cite: 3]。
出力サイズ[cite: 3]標準出力・標準エラー合計1 MiB[cite: 3]上限到達時は出力を打ち切り、上限到達のメッセージを表示する[cite: 3]。
ファイルアクセス[cite: 3]専用の一時作業ディレクトリ内に限定する方針[cite: 3]アプリ設定、ユーザーファイル、認証情報、他のアプリのデータへアクセスできないようOS権限・隔離方式を設計する[cite: 3]。
ネットワーク[cite: 3]ユーザーコードからの外部通信は初期版では禁止する方針[cite: 3]OSレベルの制御で実現可能性を検証する。Pythonコード内の機能制限だけを安全対策としない[cite: 3]。
プロセス・リソース[cite: 3]メモリ上限、CPU負荷、子プロセス起動を制限[cite: 3]具体値と実装方式は対象OS上で検証して決定する[cite: 3]。
停止操作[cite: 3]実行中に停止ボタンを提供[cite: 3]親プロセスだけでなく関連する子プロセスも停止し、UIの操作を復帰させる[cite: 3]。

セキュリティ前提：ユーザーコード実行は信頼できないコードの実行に該当する。適切な隔離を実現できない場合は、任意コード実行機能をそのまま公開しない。セキュリティレビューをリリース判定条件とする[cite: 3]。

6. AIモデル・利用不可時の動作

状態 表示・動作
モデル未導入・オンライン[cite: 3]ダウンロード容量と進捗を表示して取得する。キャンセルと再試行を可能にする[cite: 3]。
モデル未導入・オフライン[cite: 3]ダウンロード待ちであることを明示する。AI機能は無効化するが、編集・Python実行・機械的テスト・ローカル保存は継続する[cite: 3]。
モデル導入済み・オフライン[cite: 3]ローカルランタイムが正常に動作する限り、ローカルAIを利用可能とする。クラウド同期は保留する[cite: 3]。
ダウンロード・読み込み失敗[cite: 3]原因の概要、再試行、設定画面への導線を表示する。部分ダウンロードの再開可否はモデル配布方式に応じて実装する[cite: 3]。
AI応答タイムアウト・異常終了[cite: 3]AIの結果を未完了として扱い、再試行を案内する。AIに依存しない機能を停止しない[cite: 3]。

AIモデルの名称、配布元、容量、必要メモリ、ライセンス、ハッシュ検証、ダウンロード再開方式はリリース前に選定する。モデルの取得元とファイル整合性を検証し、取得したモデルの改ざんを検知できるようにする[cite: 3]。

7. コード保存・学習記録・同期

7.1 保存対象

  • 端末内：コード本文、編集中の状態、ローカル設定。ユーザーが作成したコードは原則クラウドへ送信しない[cite: 3]。
  • クラウド：ログインユーザーID、課題ID、得点、合否、テスト結果の要約、エラー種別、解決状況、学習日時、実績、同期用ID[cite: 3]。
  • コードハッシュ：必要性がある場合に限り、コード本文を復元できないハッシュ値を記録する。ハッシュだけでも他情報との組み合わせに注意する[cite: 3]。

7.2 ゲストからログインへの移行

  1. ゲスト中の学習記録は端末内に保持する[cite: 3]。
  2. ログイン時に、ローカル記録とクラウド記録の件数・対象期間を表示して統合確認を行う[cite: 3]。
  3. 重複判定には一意の記録IDを用い、同じIDは二重登録しない[cite: 3]。
  4. クラウド側とローカル側に異なる記録がある場合は、削除で上書きせず、記録ID単位でマージする[cite: 3]。

7.3 同期状態

  • synced：クラウドへの保存が確認できた[cite: 3]。
  • pending：未送信または通信待ち[cite: 3]。
  • failed：同期失敗。理由を記録し、再試行可能にする[cite: 3]。

オフライン時はローカルキューに記録し、接続回復時に再送する。同期成功が確認される前にローカル記録を削除しない。学習記録の更新競合は記録ID単位でマージし、更新日時とバージョン番号を用いて競合を検知する[cite: 3]。

8. 既習言語との構文比較

  • Pythonの変数、条件分岐、繰り返し、関数、リスト等について、Pythonと設定済み言語の例を並べて表示する[cite: 3]。
  • 初期版の比較対象はJavaとJavaScriptを基本候補とする。ユーザー設定で選択できる言語だけを表示する[cite: 3]。
  • 初期版では比較用コードの実行・コンパイルは行わず、学習用の静的な説明・例示を表示する[cite: 3]。
  • 誤った構文例を避けるため、基本比較データはレビュー済みの固定データを優先する。AI生成の説明は補助として扱い、固定データと区別して表示する[cite: 3]。

9. データ仕様（JSON例）

以下は構造例。コメントを含まない正規のJSONとして保存・送信する。日時はタイムゾーンを含むISO 8601形式とする[cite: 3]。

9.1 学習記録・エラーログ

{
  "recordId": "rec_01J9XYZ",
  "userId": "usr_12345",
  "timestamp": "2026-10-13T14:15:00+09:00",
  "language": "python",
  "errorType": "LogicError",
  "expectedOutput": "年齢は10歳です",
  "actualOutput": "年齢は15歳です",
  "explanation": "期待する結果と異なります。計算処理を確認しましょう。",
  "codeHash": "sha256:example-hash",
  "isResolved": true,
  "syncStatus": "synced"
}

errorTypeの候補：SyntaxError、RuntimeError、LogicError、Timeout、EnvironmentError、AIError。UI表示用の日本語説明は内部コードと分離する[cite: 3]。

9.2 課題採点結果

{
  "taskId": "task_python_001",
  "evaluationStatus": "completed",
  "executionStatus": "completed",
  "isPassed": true,
  "score": 85,
  "evaluationBreakdown": {
    "requirement": 45,
    "executionResult": 30,
    "codeValidity": 10
  },
  "tests": {
    "passed": 6,
    "failed": 2,
    "total": 8
  },
  "feedback": "テスト結果を確認できました。コードの構造も見直してみましょう。",
  "evaluatedAt": "2026-10-13T14:15:00+09:00"
}

例では45 + 30 + 10 = 85。isPassedは点数だけでなく、評価完了・実行状態・エラー有無・合格基準から導出する。未完了の場合はevaluationStatusをincompleteとし、合格判定を行わない[cite: 3]。

10. 画面レイアウト・状態表示

  • ヘッダー：テーマ切替、ログイン状態、AI状態、同期状態、既習言語設定[cite: 3]。
  • 左メイン：課題文、コードエディタ、整形・スニペット操作、実行・停止、自動保存状態[cite: 3]。
  • 下部または左下：標準出力、標準エラー、テスト結果、採点結果[cite: 3]。
  • 右パネル：AIアシスタント、段階的ヒント、構文比較、辞書、学習履歴[cite: 3]。
  • 狭い画面への対応：右パネルは折りたたみ・サイズ変更を可能にし、エディタとコンソールの表示領域を確保する[cite: 3]。
  • 状態表示：「AI利用可能／準備中／利用不可」「同期済み／同期待ち／同期失敗」「保存済み／保存中／保存失敗」を明確に区別する[cite: 3]。
