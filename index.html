1. アプリ概要・目的

小学生高学年から大人までのプログラミング初学者が、コードを自分で書き、実行結果やエラーを確認しながら自律的に学習できるデスクトップアプリケーションを提供する。学習モードは「自由創作」と「課題演習」の2種類を基本とし、ローカルAIによるエラー分析・段階的ヒント、自動テストによる2段階採点、ふりがな対応の辞書・他言語構文比較、マルチファイル管理、学習記録のクラウド同期を備える。

  • 初期対応言語：Python（実行対象）。Java / JavaScript は構文比較・解説の対象とし、初期版では実行環境を提供しない。
  • 保存方針：編集中のコード本文および自由創作の複数ファイル群は端末内（ローカル）に自動保存し、学習記録（メタデータ）はログイン時にクラウドへ保存・同期する。
  • AI方針：原則として端末内のローカルAIを利用する。AIが未導入または利用不可の状態でも、コード編集・実行・機械的テスト・ローカル保存を停止せず継続できる。
  • 合格基準：採点が完了し、合計80点以上、かつ構文エラー・実行時エラー・タイムアウトがないこと。

大容量のAIモデルをインストーラー本体から分離することで、初期インストーラーのファイルサイズを 約50MB〜100MB に抑える。配布・インストールの敷居を下げ、AIモデルは初回起動時またはバックグラウンドで進捗表示付きで取得する。

🛡️ セキュリティ前提（サンドボックス）

Pythonコードは任意の処理を実行し得るため、単なるタイムアウトだけでは安全性を保証できない。OSレベルの隔離・権限制限を含む実行方式を採用し、リリース前に脅威分析と安全性検証テストを実施する。

4. 課題採点仕様（2段階採点方式）

4.1 配点構成

段階 評価項目 配点 評価方法
第1段階
（機械的検証）		 要件達成度 50点 課題の要求事項（指定した変数・構文の使用、基本出力条件など）を満たしているかを評価する。チェック項目ごとの配点は課題定義に保持する。
実行結果 30点 自動テストケースの成功数・重要度に応じて算出する。テストケースの個別配点合計が必ず30点になるよう検証する。
第2段階
（AI評価）		 コード妥当性 20点 読みやすさ、適切な構造、課題に対するロジックの妥当性を評価する。ハードコーディング（丸暗記出力）の検知や改善理由の記録を行う。
合計 100点 各項目の点数を合算する。テスト配点が未設定の課題は採点を開始できない。

4.2 合否判定・部分点・フォールバック規則

  • 合計点は 0〜100 の整数とし、各評価項目の点数はそれぞれの配点上限を超えない。
  • 合格条件：「採点完了（evaluationStatus: "completed"）」かつ「合計80点以上」、かつ「構文エラー・実行時エラー・タイムアウトがない」場合のみ合格（isPassed: true）とする。
  • 部分点：テストが一部失敗した場合は成功テスト分の点数を付与し、失敗したケースの期待値と実際値（機密情報を含まない範囲）を表示する。
  • エラー発生時：構文エラー・実行時エラー・タイムアウト時は合格不可。機械的に採点できる項目のみ部分点を表示し、評価できない項目は0点と断定せず「未評価」として区別する。
  • AI評価失敗時：ローカルAIが未導入または推論失敗した場合、AI評価を必要とする採点は「採点未完了（incomplete）」とする。暫定点を合格点として扱わず、再試行または第1段階（機械的テスト結果）のみ確認できるようにする。
  • 判定の信頼性：合否は保存された点数だけでなく、採点状態と実行状態からバックエンド側で決定する。UI側の表示値のみで合否を判定しない。

4.3 段階的ヒント（ステップアップ方式）

  1. 第1段階（箇所の特定）：どの条件・処理・行付近を見直すべきか、注目ポイントを示す。
  2. 第2段階（概念・構文の解説）：関連するPythonの構文や処理の考え方を、既習言語との違いも交えて分かりやすく説明する。
  3. 第3段階（修正方針・具体例）：ユーザーがさらに助けを求めた場合に限り、短いコード例や具体的な修正方針を示す（最初から答え全文は提示しない）。

5. 実行安全性 ＆ マルチファイル・ワークスペース詳細仕様

5.1 実行安全性・制限

以下は初期実装の基準値案であり、対象PC（Windows 10/11）での負荷試験とセキュリティ検証後に最終確定する。

制限項目 初期基準案 制御・動作仕様
実行時間通常実行・各テスト：最大 5秒超過時はRustバックエンドから実行プロセスおよび全子プロセス（プロセスツリー）を強制停止し、タイムアウトとして記録する。
出力サイズ標準出力・標準エラー合計 1 MiB上限到達時はストリーム読み取りを打ち切り、プロセスを停止した上で上限到達メッセージを表示する。
ファイルアクセス専用のプロジェクト作業ディレクトリ内に限定アプリ設定、ユーザーの個人ファイル、認証情報、他アプリのデータへアクセスできないよう作業ディレクトリ隔離を設計する。
ネットワーク外部通信は初期版では原則禁止OSレベルの制御またはサンドボックス機構で実現可能性を検証する。Pythonコード内のモジュール制限（import制限）だけを安全対策としない。
プロセス・リソースメモリ上限・CPU負荷・子プロセス制限Windows Job Objects 等のOS機構を用い、メモリ上限やフォークボム（無限プロセス生成）の防止を検証・実装する。
手動停止操作実行中に「停止」ボタンを常時提供親プロセスだけでなく関連する子プロセスも確実に停止し、エディタとUIの操作を即座に復帰させる。

5.2 自由創作マルチファイル・ワークスペース詳細仕様

  • 作業ディレクトリ（CWD）の紐付け： 自由創作モードでコードを実行する際、Rust側で子プロセス（Python Embeddable）を起動する直前に Command::current_dir(&project_path) を設定する。これにより、同一フォルダ内の他ファイルを import helper や from utils import calc として標準的に読み込める。
  • Traceback解析（トレースバック・パーサー）： Pythonの実行エラー（stderr）から正規表現 File "([^"]+)", line (\d+) を用いてエラー発生元ファイル名と行番号を特定する。
  • ワンクリック・エラージャンプ導線： 呼び出し先ファイル（例: helper.py）でエラーが発生した場合、出力コンソールに「⚠️ helper.py の 4行目でエラーが発生しました [👉 該当箇所を開く]」ボタンを表示。押下時に自動で helper.py のタブへ切り替え、該当行をハイライト表示する。
  • AIによるファイル間エラー解説： エントリーファイルとエラー元ファイルの両方のコード文脈をローカルAIへ入力し、「呼び出した側のファイルではなく、呼び出された側の関数定義に問題がある」といった関係性を明示して初心者にアドバイスする。

💡 AIモデルのマルチ言語対応特性について：
本アプリで採用するローカルAIモデル（Qwen2.5-Coder / DeepSeek-Coder / Phi 等の1.5B〜3Bクラス量子化モデルを想定）は、単一のモデルファイル内にPythonだけでなくJava、JavaScript、C系言語など主要言語の構文・知識を網羅している。そのため、構文比較の対象言語を追加する際にも別のAIモデルを追加ダウンロードする必要はなく、初期導入した1つのAIモデルとアプリ内の固定辞書データの組み合わせでシームレスに対応できる。

※ AIモデルの具体的な名称、配布元URL、ファイル容量、必要メモリ、ライセンス、SHA-256ハッシュ検証方式、レジューム（再開）方式はリリース前に確定し、モデルの改ざん検知を実装する。

7. コード保存・学習記録・同期

7.1 保存対象の切り分け

  • 端末内（ローカル保存）：作成中のコード本文、エディタ状態、プロジェクト内複数ファイル（.py群）、テーマや既習言語などのローカル設定、自作シナリオデータ。ユーザーが記述したコード本文は原則クラウドへ送信しない。
  • クラウド（同期対象）：ログインユーザーID、課題ID、得点、合否、テスト結果の要約、エラー種別、解決状況、学習日時、実績バッジ、同期管理用ID。
  • コードハッシュ：同一コードでの再提出判定など必要性がある場合に限り、コード本文を復元できないSHA-256等のハッシュ値のみを記録する。

7.2 ゲスト利用からログインへの移行

  1. 未ログイン（ゲスト）状態での学習記録はすべて端末内に保持する。
  2. ログイン時に、ローカル記録とクラウド記録の件数・対象期間を提示して統合確認ダイアログを表示する。
  3. 重複判定には一意の記録ID（recordId）を用い、同一IDのレコードは二重登録しない。
  4. クラウド側とローカル側に異なる記録がある場合は、削除で上書きせず記録ID単位でマージする。

7.3 同期ステータス管理

  • synced：クラウドへの保存・同期が完了し確認できた状態。
  • pending：未送信またはオフラインによりローカル送信キューで通信回復を待っている状態。
  • failed：同期失敗。失敗理由を記録し、UI上から手動または自動で再試行可能にする。

8. 既習言語との構文比較・辞書

  • Pythonの変数、条件分岐（if）、繰り返し（for/while）、関数（def）、リスト・辞書等の基本構文について、Pythonとユーザー設定済み既習言語のコードを並べて対比表示する。
  • 初期版の比較対象言語は Java と JavaScript を基本候補とし、ヘッダーや設定で選択した言語に即座に切り替えられる。
  • 初期版では比較用コードの実行・コンパイルは行わず、学習用の静的な解説・構文対比を表示する。
  • 初学者に誤った構文例（ハルシネーション）を示さないよう、基本比較データは人間がレビューした固定データを最優先で表示する。ローカルAIによる解説は補足として扱い、固定データと明確に区別して表示する。

10. 画面レイアウト・状態表示・テーマ

  • トップバー（ヘッダー）：ダーク／ライト（黒・白）の背景テーマ切替、比較言語セレクター、AI稼働状態ピル、クラウド同期状態、ユーザーアイコンを配置する。
  • 左ナビゲーション ＆ ファイルツリー：自由創作時はフォルダ内のファイル一覧（ツリー表示）を提供し、課題演習・辞書・カルテ・アチーブメントへの切り替えを可能とする。
  • 中央メイン領域：上部にファイルタブバー（複数ファイル切替）、行番号付きPythonエディタ、実行・停止・初期化ボタン、自動保存ステータス、および下部に「実行結果コンソール（エラージャンプボタン付き）」を配置する。
  • 右サイドバー：AI学習アシスタント（ファイル間エラー特定・チャット・段階的ヒント）、現在のミニ課題カード、学習進捗バーを表示する。
  • レスポンシブ・狭い画面への対応：ウィンドウ幅に応じてパネルの折り返しや折りたたみを可能とし、エディタとコンソールの視認領域を最優先で確保する。
  • 状態の明示的区別：「AI利用可能／準備中／利用不可」「同期済み／同期待ち／同期失敗」「保存済み／保存中／保存失敗」を色とアイコンで明確に区別する。

12. 開発優先順位・実装前確定事項

12.1 実装フェーズと優先順位

  1. 優先度1：コア基盤と安全性（最優先） — Tauri v2構成、同梱Python実行・強制停止、出力制限、ローカル自動保存、作業ディレクトリ紐付け（CWD実行）、OSレベルの実行隔離のPoC検証。
  2. 優先度2：課題演習と機械的採点 — 課題定義JSONの読み込み、テストケース実行エンジン、部分点算出、合否判定、段階的ヒントUI。
  3. 優先度3：自由創作マルチファイル・エクスプローラー — ファイルツリー、タブ管理、Tracebackパーサー、エラージャンプ導線、辞書・構文比較。
  4. 優先度4：ローカルAI連携と学習支援 — AIモデルのオンデマンド取得、ローカルAI推論連携（マルチファイル関係性解説含む）、利用不可時のフォールバック。
  5. 優先度5：アカウント連携と継続利用支援 — クラウド学習記録API、ゲスト記録統合、同期競合処理、実績・バッジシステム。

13. 発展的機能・将来ロードマップ（Nice-to-have）

以下の機能は初期版（必須スコープ）完了後、コア基盤が安定した段階で順次拡張を検討する項目である。

🎯 13.1 自作シナリオ・カスタム課題作成機能

  • ユーザーが自由創作モード等で「自分だけのお題（シナリオ文・制約条件）」と「クリア判定用のテストケース（入力と期待出力のペア）」をGUIまたはJSON（9.3節の共通フォーマット）で作成・保存できる機能。
  • 作成したシナリオは課題演習と同じテスト・採点エンジンおよび実行隔離（5秒制限・1MiB制限）を通して安全に実行・自己クリア判定できる。
  • ローカルAIに「こういう問題を作りたい」と伝えてテストケースの雛形を自動生成させる作成補助機能への発展も可能。

🔌 13.2 他言語の実行環境追加（プラグイン方式）

  • 初期版ではPythonのみを実行対象とし、Java / JavaScript等は静的な構文比較および単一AIモデルによる解説で対応する。
  • 将来、他言語の「コード実行」にも対応する場合は、AIモデルの再ダウンロードは不要とし、対象言語のランタイム・コンパイラのみをオプションとして追加ダウンロード（プラグイン導入）できるアーキテクチャとする。
